Scope: `EntityGraphPage.tsx`, `Portfolios.tsx`, `Hierarchy.tsx`, `Forms.tsx`, `DataExportPage.tsx`, `CommentsPanel.tsx`, and `ActivityPanel.tsx`.

All seven requested files are present. I did not observe hardcoded business datasets in these components; the hardcoded arrays are UI options, reaction choices, skeleton rows, or filter labels rather than fake domain records.

## Top 5 Actionable Fixes

1. Wire the dead primary actions first: hierarchy `Edit`/`Add`, forms `Configure`/`Extract New`, and hierarchy search. These are visible core workflows that currently do nothing or do not affect results.
2. Fix data correctness issues in forms and comments: submit template field definitions/sample files or remove those inputs until supported; make completed-result downloads fetch full extraction details; include page number in the comments query key.
3. Add consistent mutation error/success feedback for portfolio, form, comment, and export writes. Use the existing pending states, but add toasts or inline error banners and avoid closing destructive dialogs before mutation success.
4. Move search/filter/pagination that affects correctness to the server or query keys: portfolios search, activity filters/load-more, hierarchy search, and comments page filtering should not rely on stale or partial client windows.
5. Raise DMS-grade completeness for audit/export/workspace views: add document bundle export UI, portfolio document membership management/removal, real document preview/open actions, graph provenance/export/search, and server-generated audit exports with completeness/integrity metadata.
